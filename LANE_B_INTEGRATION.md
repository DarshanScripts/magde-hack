## 3. Contract change (already in `contract.ts` and `plan.md`)

```ts
export type Token = {
  label: string;          // from labels.json or "?"
  conf: number;
  t: number;
  top?: [string, number][];
  question?: "yn" | "wh"; // NEW: brows raised = yes/no question, lowered = W-question
  negation?: boolean;     // NEW: head shake during the sign
};
```

`POST /api/sentence` body gets two fields (backwards compatible; default `null` / `false`):
```json
{ "tokens": [...], "history": [...], "profile": {"name": "Aditya"}, "question": "yn" | "wh" | null, "negation": false }
```
- Utterance flags from the token buffer: `question` = the last non-empty `question` among the tokens, else `null`;
  `negation` = `true` if any token has `negation`.
- Add rule 8 to the system prompt (plan.md F4):
  ```
  8. question = "yn" → phrase it as a yes/no question ("MORGEN NACHMITTAG" → "Geht es morgen Nachmittag?").
     question = "wh" → phrase it as a W-question (wann/was/wo/wer/wie). negation = true → negate the statement ("HEUTE" → "Heute geht es nicht.").
  ```
- Show the flags on the chips (e.g. a "?" or "¬" badge), so the signer sees what was detected.

## 4. Mount the camera when the call starts (main page, F9)

`SignCamera` uses browser-only APIs → import it with `ssr: false` (same as `/record` does):

```tsx
"use client";
import dynamic from "next/dynamic";
import type { SignStatus, Token } from "@/lib/contract";

const SignCamera = dynamic(() => import("@/components/SignCamera"), { ssr: false });
```

Render it only while the call is active. Mounting starts the webcam and loads the models; unmounting stops
the webcam and closes the WebSocket, so "Auflegen" releases the camera automatically:

```tsx
const [chips, setChips] = useState<Token[]>([]);
const [signStatus, setSignStatus] = useState<SignStatus>({ state: "rest", fps: 0, online: false });

const onToken = useCallback((t: Token) => {
  setChips((c) => [...c, t]);          // "?" → grey chip, never sent to /api/sentence
  // restart your 1.5 s "send sentence" timer here (F9 step 2.2)
}, []);

{/* left column (~55 %) */}
{inCall ? (
  <SignCamera mode="infer" onToken={onToken} onStatus={setSignStatus} />
) : (
  <div>{/* placeholder / dial bar hint */}</div>
)}
```

When you build the request:
```ts
const real = chips.filter((c) => c.label !== "?");
const body = {
  tokens: real.map((c) => c.label),
  history: turns.slice(-6),
  profile: { name },
  question: [...real].reverse().find((c) => c.question)?.question ?? null,
  negation: real.some((c) => c.negation),
};
```

Notes:
- **Props:** always `mode="infer"` on the main page. `recordLabel`, `signer`, `onRecorded` are only for `/record`.
- **Pass stable callbacks** (`useCallback`) if you like; `SignCamera` reads the latest props through a ref, so
  changing callbacks does not restart the camera either way.
- **Size:** it renders a `w-full aspect-[4/3]` box; put it in a sized container. Don't add your own mirroring CSS.
- **Load time:** first mount downloads the MediaPipe wasm + 3 models (~32 MB, from jsDelivr and Google storage,
  cached afterwards) → about 2–5 s until the overlay appears. If that delay at "Anrufen" bothers you, you can
  mount it as soon as the page loads (hidden) instead; your choice.
- **Status dot:** `signStatus.online === false` → sign service offline; `state === "signing"` → red; else grey.
  `SignCamera` also shows these badges itself.
- **Camera vs. LiveKit:** per plan the signer publishes **no camera and no mic**, only the `tts` track. If you do
  publish video, Chrome lets both `getUserMedia` calls share the webcam on the same page.
- **Keep `?mock=1`** working; it's the fallback if the camera/model fails during the demo.

## 5. Run it on your laptop

One-time Python setup (Python 3.12). The service imports torch even without a model:
```bash
cd sign
python3.12 -m venv .venv
# no NVIDIA GPU: CPU torch is enough to run the service (smaller download)
.venv/bin/pip install fastapi==0.162.2 "uvicorn[standard]==0.54.0" numpy==2.5.4 scikit-learn==1.9.1 torch==2.14.1 \
  --extra-index-url https://download.pytorch.org/whl/cpu
# or, with an NVIDIA GPU (CUDA 12.6 driver): .venv/bin/pip install -r requirements.txt
```

Start everything (from the repo root):
```bash
SIGN_FAKE=HALLO,TERMIN,WOLLEN,MORGEN,NACHMITTAG ./run.sh /    # sign service :8765, Next :3000, opens the main page
./stop.sh                                                    # stops both (+ Lane B's GPU Chrome if present)
```
Or manually:
```bash
cd sign && SIGN_FAKE=HALLO,TERMIN,WOLLEN,MORGEN,NACHMITTAG .venv/bin/uvicorn server:app --port 8765
cd web && npm run dev
```

**`SIGN_FAKE` = testing without a trained model.** The real pipeline runs (webcam, MediaPipe, segmentation,
brow/head-shake detection), but instead of the classifier, each detected sign emits the next gloss from the
list (cycling). So: raise your hand, move it, lower it → `HALLO` chip; again → `TERMIN`; … Raise your eyebrows
while doing it → `question: "yn"`; shake your head → `negation: true`. That exercises the whole loop
onToken → /api/sentence → TTS → callee. Without `SIGN_FAKE` and without a model, no tokens arrive
(the service answers "model not loaded").

Rules:
- The signer page must be **`http://localhost:3000`**, not the ngrok https URL: an https page cannot open
  `ws://localhost:8765`. The callee uses ngrok as before.
- The sign service accepts only `localhost` origins.
- Service check: `curl localhost:8765/health` → `"model": false, "fake": true` in fake mode.
- Override the service URL with `NEXT_PUBLIC_SIGN_WS_URL` if needed (default `ws://localhost:8765/ws`).

## 6. Done when (on your laptop, with `SIGN_FAKE`)

1. Before the call: no camera light, no webcam prompt.
2. Press "Anrufen" → the camera with hand/face overlay appears in the left column within a few seconds; badge "rest".
3. Three hand movements → chips `HALLO TERMIN WOLLEN` → after 1.5 s a German sentence in the feed and spoken on the callee device.
4. Same with raised eyebrows → the sentence comes out as a question; with a head shake → negated.
5. "Auflegen" → camera light off, dial bar back.
6. `npx tsc --noEmit && npm run lint` pass.
