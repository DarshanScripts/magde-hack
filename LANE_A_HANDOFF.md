## 4. Main page integration (F9)

```tsx
"use client";
import dynamic from "next/dynamic";
import type { SignStatus, Token } from "@/lib/contract";

const SignCamera = dynamic(() => import("@/components/SignCamera"), { ssr: false });
const SENTENCE_GAP_MS = 4000;
```

Mount only during the call. Mounting starts webcam + models; unmounting (on "Auflegen") stops the webcam and
closes the WebSocket:

```tsx
{inCall ? <SignCamera mode="infer" onToken={onToken} onStatus={setSignStatus} /> : <Placeholder />}
```

Token buffer and utterance end:

```tsx
const chipsRef = useRef<Token[]>([]);
const [chips, setChips] = useState<Token[]>([]);
const timer = useRef<ReturnType<typeof setTimeout>>(undefined);

const onToken = useCallback((t: Token) => {
  if (t.label === "?") return;                 // optional: show a grey chip briefly, never send it
  chipsRef.current = [...chipsRef.current, t];
  setChips(chipsRef.current);
  clearTimeout(timer.current);
  timer.current = setTimeout(sendUtterance, SENTENCE_GAP_MS);
}, [sendUtterance]);
// Enter → sendUtterance() now; Backspace → drop last chip; Esc → clear chips
```

Request body (`/api/sentence`):

```ts
const tokens = chipsRef.current;
const body = {
  tokens: tokens.map((t) => t.label),
  history: turns.slice(-6),
  profile: { name },
  question: [...tokens].reverse().find((t) => t.question)?.question ?? null,  // "yn" | "wh" | null
  negation: tokens.some((t) => t.negation),
};
```

Show the flags on the chips (`?` for `question`, `¬` for `negation`).

**Why 4 s, not the 1.5 s in plan.md:** the signer lowers the hands between signs (see §6). Measured on real
signing: consecutive signs are 2.5 s apart (median), up to ~4.6 s. 1.5 s would cut every sentence into single
words. Enter ends the utterance immediately.

Other notes:
- Always `mode="infer"` on the main page; `recordLabel`, `signer`, `onRecorded` are only for `/record`.
- `SignCamera` renders `w-full aspect-[4/3]`; give it a sized container. No extra mirroring CSS.
- First mount downloads ~32 MB (MediaPipe wasm + 3 models, cached afterwards): 2–5 s until the overlay shows.
- Status dot from `onStatus`: `online === false` → offline; `state === "signing"` → red; else grey.
- Signer publishes no camera/mic to LiveKit (only the `tts` track), per plan.
- Keep `?mock=1` (label buttons calling the same `onToken`) as the demo fallback.

## 5. Sentence prompt rule 8 (`/api/sentence`, F4)

Add to the system prompt and pass the two fields into the user message:
```
8. question = "yn" → phrase it as a yes/no question ("MORGEN NACHMITTAG" → "Geht es morgen Nachmittag?").
   question = "wh" → phrase it as a W-question (wann/was/wo/wer/wie). negation = true → negate the statement ("HEUTE" → "Heute geht es nicht.").
```

## 6. Run and test on your laptop

One-time Python setup (3.12; CPU torch is enough for the service):
```bash
cd sign && python3.12 -m venv .venv
.venv/bin/pip install fastapi==0.162.2 "uvicorn[standard]==0.54.0" numpy==2.5.4 scikit-learn==1.9.1 torch==2.14.1 \
  --extra-index-url https://download.pytorch.org/whl/cpu
# NVIDIA GPU with CUDA 12.6 driver instead: .venv/bin/pip install -r requirements.txt
```

Start / stop (repo root):
```bash
./run.sh /          # sign service :8765 + Next :3000, opens the main page
./stop.sh
```

Two ways to get tokens:
- **Real model (v0, included):** sign any of the 15 p0 signs (HALLO, DANKE, TSCHUESS, JA, NEIN, WIEDERHOLEN,
  NAME, TERMIN, WOLLEN, HEUTE, MORGEN, NACHMITTAG, UHR, UNTERSUCHUNG, SCHMERZ). Trained only on person 2,
  so on you it will often return `?` or wrong labels; that's expected.
- **`SIGN_FAKE`** (deterministic, for testing the loop): `./stop.sh && SIGN_FAKE=HALLO,TERMIN,WOLLEN,MORGEN,NACHMITTAG ./run.sh /`.
  Each detected hand movement (raise hand, move, lower) emits the next gloss from the list, cycling.
  Brows/head shake flags are still real. Remove `SIGN_FAKE` (restart) to use the model again.

How signing works (tell the tester):
- Rest = hands down / out of view. **Lower the hands between signs.** A sign ends ~150 ms after the hands drop.
  Chained signs with hands kept up merge into one segment (known limitation).
- Raised brows during a sign → `question: "yn"`; lowered → `"wh"`; head shake → `negation: true`.

Rules:
- Signer page must be **`http://localhost:3000`** (an https/ngrok page cannot reach `ws://localhost:8765`).
  The callee uses ngrok as before.
- The sign service accepts only localhost origins. Check it: `curl localhost:8765/health` → `"model": true`.
- `/record` (infer mode) is a quick standalone check of recognition and the sentence builder.
